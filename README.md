# 🔑 우리학교 키박스

> 학교 업무에 자주 쓰는 사이트 계정과 학교 정보를
> **키박스 잠금 비밀번호로 암호화해 브라우저에 보관하는 학교 행정실용 로컬 키박스**입니다.

[👉 바로 사용하기](https://sen-vip.github.io/school-keybox/)

---

## 📌 소개

**우리학교 키박스**는 학교 행정실에서 자주 사용하는 사이트 계정, 학교 기본정보, 계좌·결제 정보를 한 곳에서 찾고 복사할 수 있도록 만든 웹 도구입니다.

별도 서버나 회원가입 없이 브라우저에서 동작하며, 입력한 키박스 데이터는 **키박스 잠금 비밀번호에서 만든 암호화 키로 암호화한 뒤 현재 브라우저에 저장**합니다.

> 보안을 강화했지만 전용 비밀번호 관리도구를 완전히 대신하는 제품은 아닙니다. 공동인증서 비밀번호, 금융·은행 비밀번호, 최고권한 관리자 계정처럼 특히 중요한 인증정보는 전용 비밀번호 관리도구 사용을 권장합니다.

## ✨ 주요 기능

### ⚡ 빠른복사

* 즐겨찾기한 사이트의 ID·PW 빠른 복사
* 비밀번호는 화면에 기본 마스킹
* 복사할 때 비밀번호를 화면에 표시하지 않음
* 검색과 즐겨찾기로 반복 로그인 업무 단축

### 🌐 사이트 계정 관리

* 사이트명
* 아이디
* 비밀번호
* URL
* 메모
* 즐겨찾기 여부

비밀번호는 기본적으로 가려져 있으며, 눈 버튼으로 확인한 경우에도 약 10초 뒤 다시 가려집니다.

### 🏫 학교 정보 관리

학교명, 기관번호, 사업자등록번호, 대표 전화번호, 주소 등 반복해서 입력하는 학교 정보를 정리하고 복사할 수 있습니다.

### 🏦 계좌·결제 정보 관리

은행 계좌와 업무용 결제수단 정보를 필요한 항목 중심으로 정리할 수 있습니다. 민감한 값은 기본적으로 화면에서 가려집니다.

### 🔍 검색

사이트명, 아이디, 메모, 학교 정보, 계좌·결제 정보 등을 한 번에 검색합니다. 검색은 잠금 해제 후 메모리에 복호화된 데이터에서 수행하며 별도의 평문 검색 인덱스를 브라우저 저장소에 만들지 않습니다.

## 🔐 보안 저장 방식

v3.3.0부터 기존 평문 localStorage 저장 방식을 사용하지 않습니다.

> v3.3.2에서는 잠금 비밀번호의 최소 길이를 **8자 이상**으로 조정하고, 키박스를 열어 둔 채 자리를 비우는 상황을 줄이기 위해 **5분 동안 사용하지 않으면 자동으로 잠기도록** 변경했습니다. 비밀번호를 눈 버튼으로 확인한 경우에는 기존처럼 10초 뒤 자동으로 다시 가려집니다.

* Web Crypto API 사용
* AES-GCM 256bit 암호화
* PBKDF2-HMAC-SHA-256으로 키박스 잠금 비밀번호에서 키 생성
* 랜덤 salt 및 암호화 시 랜덤 IV 사용
* 키박스 잠금 비밀번호 자체는 저장하지 않음
* 암호화 키는 잠금 해제 중 메모리에서만 사용
* 새로고침·브라우저 재실행 시 다시 잠금 해제 필요
* 5분 동안 사용하지 않으면 자동 잠금
* 직접 `🔒 잠금` 가능

브라우저 저장소에는 카드 원문 대신 암호화된 vault 정보만 남도록 구성했습니다.

### 기존 사용자 데이터

이전 버전에서 평문으로 저장한 데이터가 발견되면 바로 삭제하지 않고 **보안 전환 화면**을 먼저 표시합니다.

1. 기존 데이터 읽기
2. 키박스 잠금 비밀번호 설정
3. 새 암호화 vault 생성
4. 암호화 데이터의 복호화 검증
5. 검증 성공 후에만 이전 평문 저장 데이터 삭제

마이그레이션 중 암호화 또는 검증이 실패하면 기존 데이터를 먼저 지우지 않습니다.

## 🔒 잠금·화면 보호

### 키박스 잠금 비밀번호

처음 사용할 때 8자 이상의 키박스 잠금 비밀번호를 설정합니다.

키박스 잠금 비밀번호는 서버로 보내거나 브라우저 저장소에 보관하지 않습니다. 따라서 **키박스 잠금 비밀번호를 잊으면 기존 암호화 데이터를 복구할 수 없습니다.**

### 자동 잠금

* 5분 미사용 시 자동 잠금
* 새로고침 시 잠금 상태로 시작
* 상단 `🔒 잠금` 버튼으로 즉시 잠금
* 탭이 백그라운드로 이동하면 열어 둔 비밀번호를 다시 마스킹

### 화면 가리기

상단 `👁 화면 가리기`를 누르면 화면에 보이는 민감정보를 빠르게 가릴 수 있습니다. 이 기능은 주변 사람의 화면 열람을 줄이기 위한 보조 기능이며 데이터 암호화를 대신하지 않습니다.

## 📊 엑셀 기능

엑셀은 **업무정보 이동·정리용**으로 사용하고, 비밀번호까지 포함한 전체 백업에는 암호화 백업을 권장합니다.

### 안전한 엑셀 저장

기본 엑셀 다운로드에서는 다음 정보를 제외합니다.

* 사이트 로그인 비밀번호
* 민감한 학교 기본정보 값

비밀번호·민감값을 포함하는 옵션은 기본 OFF이며, 직접 선택하면 평문 엑셀 위험 안내를 한 번 더 확인해야 다운로드할 수 있습니다.

* 안전한 엑셀: `..._KEY_SAFE_날짜시간.xlsx`
* 민감정보 포함 엑셀: `..._KEY_PASSWORD_날짜시간.xlsx`

### 빈 엑셀 양식

기본 입력 양식에도 실제 비밀번호나 민감값을 자동으로 넣지 않습니다.

### 엑셀 가져오기

엑셀 파일은 브라우저에서 읽고 키박스 데이터로 반영한 뒤 암호화하여 저장합니다. 서버 업로드 기능은 사용하지 않습니다.

안전한 엑셀처럼 비밀번호 열이 없는 파일을 다시 가져와 `엑셀처럼 맞추기`를 사용하더라도 기존 키박스 비밀번호를 빈 값으로 덮어쓰지 않도록 처리했습니다.

## 💾 암호화 백업

즐겨찾기, 순서, 비밀번호까지 전체 상태를 보관하려면 `🔐 암호화 백업`을 사용합니다.

* 파일 확장자: `.keybox`
* 평문 카드 데이터를 백업 파일에 다시 만들지 않음
* 현재 암호화 vault를 그대로 백업
* 다른 브라우저에서 불러올 때 해당 백업의 키박스 잠금 비밀번호 필요
* 잘못된 비밀번호나 손상된 파일은 현재 데이터를 교체하기 전에 검증

이전 버전의 평문 JSON 백업도 호환을 위해 불러올 수 있으나, 경고 확인 후 현재 키박스 잠금 비밀번호로 즉시 암호화 저장합니다.

## 🖨️ 인쇄 / PDF 저장

정리된 내용을 인쇄하거나 PDF로 저장할 수 있습니다. 인쇄 직전 화면에서 열어 둔 비밀번호는 다시 가립니다.

출력물은 암호화된 브라우저 저장소와 달리 종이나 PDF 자체에 정보가 노출될 수 있으므로 별도로 관리해 주세요.

## 🧭 사용 방법

1. [우리학교 키박스](https://sen-vip.github.io/school-keybox/)에 접속합니다.
2. 처음 사용하는 경우 8자 이상의 키박스 잠금 비밀번호를 설정합니다.
3. 기존 사용자는 안내에 따라 기존 데이터를 암호화 방식으로 전환합니다.
4. 사이트 계정과 필요한 학교 정보를 입력합니다.
5. 필요한 항목을 검색하고 복사합니다.
6. 사용을 마치면 `🔒 잠금`을 누릅니다.
7. 비밀번호까지 백업하려면 `.keybox` 암호화 백업을 사용합니다.

## ⚠️ 꼭 확인해 주세요

암호화 저장은 **브라우저에 저장된 파일·데이터가 그대로 노출되는 위험을 줄이는 기능**입니다. 모든 보안 위험을 없애지는 못합니다.

* 잠금 해제 중에는 앱이 업무를 위해 복호화된 데이터를 메모리에서 사용합니다.
* 공용 PC나 여러 사람이 같은 브라우저 프로필을 쓰는 환경에서는 사용을 권장하지 않습니다.
* 악성 프로그램, 과도한 권한을 가진 브라우저 확장 프로그램, 사이트 코드 변조 등의 위험은 별도로 존재합니다.
* 키박스 잠금 비밀번호는 복구할 수 없으므로 안전하게 관리해 주세요.
* 브라우저 저장정보 삭제, PC 교체, 브라우저 변경 전에는 암호화 백업을 만들어 주세요.
* 기관의 정보보안 지침이 있는 경우 해당 지침을 우선해 주세요.

### 저장을 특히 권장하지 않는 정보

* 공동인증서 비밀번호
* 금융·은행 서비스 비밀번호
* 최고권한 관리자 계정
* 한 번 유출되면 피해가 큰 핵심 인증정보

이런 정보는 브라우저 키박스보다 전용 비밀번호 관리도구를 권장합니다.

## 🛡️ 네트워크·코드 보호

* 사용자 키박스 데이터를 저장하기 위한 서버·DB 없음
* 카드 생성·수정·검색·암호화·복호화를 브라우저에서 처리
* 불필요한 외부 분석·광고·추적 코드 없음
* CSP 적용으로 외부 연결 범위 제한
* 사용자 입력을 이벤트 속성에 직접 삽입하지 않도록 이벤트 처리 구조 정리
* 엑셀 호환을 위한 XLSX 외부 스크립트 사용
* 화면 글꼴(SUIT) 스타일시트를 외부 CDN에서 불러옴

> 외부 CDN 의존성을 완전히 제거한 구조는 아니므로, 배포 환경의 코드와 의존성 관리 역시 중요합니다.

### 배포 주소도 보안 경계입니다

브라우저의 저장소와 페이지 접근 권한은 URL의 폴더명이 아니라 **origin(프로토콜 + 호스트 + 포트)** 단위로 구분됩니다. 따라서 여러 웹앱을 같은 `sen-vip.github.io` 호스트의 서로 다른 경로에 배포하면 서로 같은 origin을 사용합니다.

키박스에 민감정보를 실제로 보관할 경우에는 다른 실험용 웹앱과 분리된 **전용 호스트** 사용을 권장합니다. 예를 들어 키박스만 별도의 Vercel 프로젝트 주소 또는 별도 커스텀 도메인으로 배포하면 브라우저 보안 경계가 분리됩니다.

이 저장소의 `vercel.json`에는 Vercel 배포 시 다음 헤더가 적용되도록 보안 설정을 포함했습니다.

* `frame-ancestors 'none'` / `X-Frame-Options: DENY`
* `X-Content-Type-Options: nosniff`
* `Referrer-Policy: no-referrer`
* 제한적인 `Permissions-Policy`
* `Cross-Origin-Opener-Policy: same-origin`

GitHub Pages에서는 `vercel.json` 헤더 설정이 적용되지 않으므로, GitHub Pages 사용 시에는 HTML의 CSP meta 정책만 적용됩니다.
